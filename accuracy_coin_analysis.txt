--- FAIL 16: Page 19, Test 8 — "$2007 Stress Test" ---
  Kod błędu: 2
  Komunikat: "Reading from $2007 should set up the PPU Read Buffer two PPU
              cycles after the CPU read ends; likely wrong PPU cycle or
              missing dummy nametable reads."

  OPIS TESTU (TEST_2007_Stress, linia ~2436):
    Test czyta $2007 na każdym PPU cyklu visible scanline i sprawdza
    co trafia do PPU Read Buffer. PPU DATA State Machine działa w 3 cykle:
    1. CPU read kończy się → state machine start
    2. 1 PPU cycle później: ALE (address latch setup)
    3. 2 PPU cycle później: idle
    4. 3 PPU cycle później: read from memory → update read buffer

    Test weryfikuje że read buffer jest ustawiony poprawnie 2 PPU cykle
    po zakończeniu CPU read.

  [P] PPU2C02::readPPUData():
    uint8_t data = ppu_data_buffer;
    ppu_data_buffer = ppuRead(busAddr);
    To czyta buffer i natychmiast ładuje nową wartość. Ale w rzeczywistości:
    - CPU read kończy się na końcu cyklu CPU (M2 low)
    - PPU DATA state machine startuje
    - 3 PPU cykle później read buffer jest aktualizowany

    Problem: readPPUData() aktualizuje buffer natychmiast, nie po 3 PPU
    cyklach. W trakcie visible scanline, to powoduje że buffer jest
    aktualizowany w złym momencie — powinien być aktualizowany 3 PPU cykle
    po CPU read, ale jest aktualizowany natychmiast.

    Dodatkowo: w trakcie visible scanline, PPU wykonuje background/sprite
    fetch co 2 cykle. PPU DATA state machine działa co 3 cykle. To powoduje
    konflikty (ALE + Read jednocześnie) które mogą prowadzić do unstable
    reads z adresów hybrydowych.

  [F] 1. Zaimplementować PPU DATA State Machine:
       - Gdy CPU read z $2007 kończy się, zaplanuj aktualizację read buffer
         3 PPU cykle później.
       - W trakcie tych 3 cykli, PPU może wykonywać normalne fetche (BG/sprite).
       - Aktualizacja read buffer używa adresu z v register, ale może być
         zakłócona przez normalne fetche (hybrydowy adres).
     2. To wymaga śledzenia PPU DATA state w clock() i aktualizacji
        ppu_data_buffer w odpowiednim cyklu.
     3. Trzeba też obsłużyć unstable reads (ALE + Read jednocześnie).

  [R] Duża zmiana w PPU. Wpłynie na FAIL 17 (ALE + Read) i wszystkie
      testy czytające $2007.
